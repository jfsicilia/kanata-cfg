# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This is a [kanata](https://github.com/jtroo/kanata) keyboard remapping configuration. The repo lives at `~/settings/linux/dotfiles/kanata-cfg/` and is symlinked or copied to `~/.config/kanata/`. The main entry point is `kanata.kbd`, which assembles everything via `(include ...)` directives.

## Reloading kanata

There is no build step. To apply changes, reload kanata from the keyboard itself:

- `opts+k` — live-reload kanata (equivalent to `lrld`)
- `opts+lsft+k` — run `kanata_sync.sh` (regenerates autogenerated sections of `kanata.kbd`) then reload
- `opts+rsft+k` — restart the `kwanata` systemd service

`opts` is the physical `rctl` key (or physical `esc` key).

## File Architecture

```
kanata.kbd          ← main entry: includes everything in order
templates.kbd       ← core macros (fast_th, map_keys, map_layers, alt_char, …)
help.kbd            ← help message strings as defvar
setup.kbd           ← defsrc, defvar (key aliases), defvirtualkeys, default layer
layers/             ← deflayermap definitions for each domain layer
layers_toggle/      ← toggle variable definitions (e.g. $toggle_omni_layer)
actions/            ← action variable definitions, split by interface and app
bookmarks.kbd       ← bookmark action definitions
info/               ← mapping reference docs (mappings_*.md)
```

### Core templates (`templates.kbd`)

All tap-hold bindings go through `(t! fast_th tap hold)` rather than raw `tap-hold`. This detects fast typing (via `vk_fast_typing`) and suppresses modifier activation during quick key sequences.

Key templates:
- `fast_th tap hold` — fast-typing-aware tap-hold with global timings
- `th tap hold` — plain tap-hold-press using global timings (no fast-typing guard)
- `2x action` / `3x action` — double/triple-tap detectors
- `map_keys action ignore_keys` — fills a layer with all alpha/symbol keys (pass `_` as action for pass-through)
- `map_layers action layer ignore_keys` — wires modifier keys (f/j for lctl, s/l for lalt, a/; for lmet, d for lsft, k for rsft) to `+modifier` sub-layer variants
- `mod_key_layer mod_key spc_action lsft+spc lsft+spc` — generates a complete domain layer with shift variants in one call
- `char|alt_char letter` — outputs the letter normally, or with tap-dance accents when `vk_alt_chars` is active (Spanish mode)

### Layer system

Every key with hold behavior produces two effects: a **tap** (the letter) and a **hold** (a domain layer). Domain layers are named `<mod>_layer` (e.g. `omni_layer`, `tabs_layer`, `modA_layer`). When a modifier key (f, s, a, j, l, ;) is also held inside a domain layer, a `+modifier` sub-layer is toggled on top (e.g. `modA+lctl_layer`).

The `layers_toggle/` directory contains `$toggle_<name>_layer` variables that bind the correct combination of layer toggles and held modifiers.

### Interface / app dispatch system

Actions that vary per application use a **virtual-key dispatch** pattern:

1. `actions/*.iface.kbd` — interface files with `switch` statements checking which app's virtual key is active (e.g. `(input virtual vk_nvim)`)
2. `actions/<app>/<app>_defs.kbd` — per-app variable definitions implementing the interface
3. `actions/<app>/<app>_<interface>.kbd` — per-app bindings for a specific interface

The bottom of `kanata.kbd` (below the `@iface@` comment) is **autogenerated** by `kanata_sync.sh`. Do not edit it by hand. The script scans `actions/` subdirectories to produce `defvirtualkeys` and `include` statements. Per-app files can carry a numeric priority suffix (e.g. `nvim_groups.1.kbd` = checked at priority 1 in `switch`; lower numbers win).

App focus is detected externally (e.g. via a window manager hook) which toggles the appropriate `vk_<app>` virtual key.

### Naming conventions

- Layer files: `layers/layer_<domain>.kbd`
- Toggle files: `layers_toggle/toggles_<group>.kbd`
- Interface files: `actions/actions_<domain>.iface.kbd`
- App action files: `actions/<app>/<app>_<domain>.kbd`
- App-specific variables: `<app>_<action_name>` (e.g. `nvim_file_explorer`)

### Key alias variables (`setup.kbd`)

All physical key names are aliased to descriptive variable names in `(defvar ...)`. The pattern is `key|layer_name physical_key`. For example `$tab|open tab` means the tab key can be referenced as `$tab|open` and its hold activates `open_layer`. This makes layer and action definitions self-documenting.

### `;;""` marker

Lines ending in `;;""` are significant — they mark section boundaries that tooling (the align-values skill) uses when formatting variable value columns.
